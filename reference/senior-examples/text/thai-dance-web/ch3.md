# บทที่ 3 วิธีการดำเนินงาน

งานวิจัยนี้เป็นการศึกษาและพัฒนา “เว็บแอปพลิเคชันสำหรับการเรียนรู้รำวงมาตรฐานไทยสำหรับชาวต่างชาติ” โดยใช้เทคโนโลยี Computer Vision ผ่านโมเดล MediaPipe Pose และ MediaPipe Hands เพื่อวิเคราะห์และประเมินความถูกต้องของท่ารำแบบเรียลไทม์ ระบบหลักถูกพัฒนาในรูปแบบ Web Application ด้วยภาษา JavaScript ร่วมกับ React Framework และใช้ภาษา Python สำหรับวิเคราะห์ข้อมูลมุมข้อต่อ คำนวณค่าเฉลี่ยของท่ารำต้นแบบ และแปลงข้อมูลให้อยู่ในรูปแบบที่สามารถนำไปใช้งานบนเว็บแอปพลิเคชันได้ โดยคณะผู้จัดทำได้แบ่งขั้นตอนการดำเนินงานดังนี้

## 3.1 กำหนดสภาพแวดล้อมของการพัฒนา

การพัฒนาโครงงานนี้ออกแบบขึ้นภายใต้สภาพแวดล้อมแบบผสมผสาน (Hybrid Environment) โดยในส่วนของการจัดเตรียมชุดข้อมูล การฝึกสอนแบบจำลองปัญญาประดิษฐ์ (Model Training) และการวิเคราะห์โมเดลเชิงเรขาคณิต จะใช้ภาษา Python เป็นภาษาหลัก เนื่องจากมีระบบนิเวศของไลบรารีที่รองรับงานด้านคอมพิวเตอร์วิทัศน์อย่างครบถ้วน และในส่วนของการพัฒนาเว็บแอปพลิเคชันเพื่อประมวลผลแบบเรียลไทม์บนฝั่งผู้ใช้งาน (Client-side Real-time Processing) จะใช้ภาษา JavaScript เพื่อให้ระบบสามารถรันบนเว็บเบราว์เซอร์ได้อย่างลื่นไหล

3.1.1 ภาษาโปรแกรม (Programming Languages)

1. ภาษาไพธอน (Python): ภาษาโปรแกรมระดับสูงที่มีโครงสร้างไวยากรณ์เรียบง่าย เอื้อต่อการพัฒนาโปรแกรมอย่างรวดเร็ว (Rapid Prototyping) และได้รับความนิยมอย่างแพร่หลายในชุมชนนักวิจัยด้านการเรียนรู้ของเครื่อง (Machine Learning)
2. ภาษาจาวาสคริปต์ (JavaScript - ES6+): ภาษาโปรแกรมหลักที่ใช้ในการควบคุมตรรกะเชิงเรขาคณิตและการคำนวณตัดเกณฑ์คะแนนบนเว็บแอปพลิเคชัน เพื่อรองรับการประมวลผลพิกัดร่างกายจากกล้องเว็บแคมแบบเวลาจริง (Real-time) โดยไม่ต้องพึ่งพาพลังการประมวลผลจากเซิร์ฟเวอร์

## 3.3 การเตรียมชุดข้อมูล

ในการพัฒนาลอจิกและเกณฑ์การให้คะแนนสำหรับระบบประเมินท่ารำไทย ผู้จัดทำได้กำหนดกระบวนการจัดเตรียมชุดข้อมูลมาตรฐานเพื่อนำมาคำนวณหาค่าเฉลี่ยทางสถิติและขอบเขตองศาข้อต่อที่ถูกต้อง โดยแบ่งขั้นตอนการดำเนินงานออกเป็น 3 ขั้นตอนหลัก ดังนี้

3.3.1 การจัดหาและดึงเฟรมภาพจากวิดีโอต้นแบบ

ผู้จัดทำทำการรวบรวมวิดีโอสาธิตการรำที่ถูกต้องจากผู้เชี่ยวชาญ จากนั้นนำมาประมวลผลผ่านชุดคำสั่งภาษา Python ร่วมกับคลังโปรแกรม OpenCV เพื่อทำการดึงเฟรมภาพ (Frame Extraction) ออกมาจากไฟล์วิดีโอต้นแบบ (.mp4) โดยระบบจะทำการคำนวณระยะห่างในการบันทึกเฟรมภาพโดยอัตโนมัติ (Dynamic Frame Interval) เพื่อสกัดภาพนิ่งออกมาให้ได้จำนวนประมาณ 60 ภาพต่อหนึ่งวิดีโอสาธิตอย่างทั่วถึง ทั้งนี้เพื่อลดความซ้ำซ้อนของข้อมูลและคัดเลือกเฉพาะภาพท่ารำที่ชัดเจนสำหรับนำไปวิเคราะห์ในขั้นตอนถัดไป

3.3.2 การตรวจจับและสกัดพิกัดสรีระร่างกาย

นำภาพนิ่งที่สกัดได้เข้าสู่กระบวนการตรวจจับพิกัดข้อต่อด้วยเทคนิคคอมพิวเตอร์วิทัศน์ โดยใช้เทคโนโลยี MediaPipe Pose Solution ในการระบุตำแหน่งข้อต่อสำคัญบนร่างกายจำนวน 33 จุด พิกัดเชิงพื้นที่ (X, Y) ที่ได้จะถูกนำมาคำนวณความสัมพันธ์ทางเรขาคณิตผ่านชุดคำสั่ง Python เพื่อจัดเก็บพารามิเตอร์สำคัญในรูปแบบไฟล์ JSON ดังนี้:

องศาข้อศอกและความตึงของแขน (Elbow Angle & Arm Ratio)

คำนวณจากข้อต่อส่วนไหล่ ศอก และข้อมือ โดยเลือกระบบการตรวจวัดจากแขนข้างหลักที่ยกสูงกว่า (แกน Y ต่ำกว่า) เป็นแกนอ้างอิง

**องศาไหล่เทียบกับลำตัว (Shoulder Angle):**วัดความกางของไหล่กับสะโพก

**ช่วงล่างและการย่อตัว (Knee & Hip Angle):** คำนวณองศาข้อต่อบริเวณสะโพก หัวเข่า และข้อเท้า เพื่อตรวจวัดความลึกของการย่อตัวตามหลักนาฏศิลป์

**การเอียงศีรษะ (Neck Tilt):** คำนวณองศาระหว่างจุดกึ่งกลางไหล่ทั้งสองข้างกับพิกัดจมูก

**สถิติขอบเขตเกณฑ์คะแนน:** นำค่าองศาที่สกัดได้ทั้งหมดมาหาขอบเขตบนและล่างโดยใช้ค่าเปอร์เซ็นไทล์ที่ 10 (Percentile 10) และเปอร์เซ็นไทล์ที่ 90 (Percentile 90) เพื่อสร้างช่วงคะแนนมาตรฐานที่ยืดหยุ่นและเสถียร

3.3.3 การคัดแยกกลุ่มข้อมูลและปริมาณชุดข้อมูลภาพเฉลี่ยมาตรฐาน

จากการทดสอบพบข้อจำกัดทางเทคนิคในบางท่วงท่า (เช่น "ท่าจีบส่งหลัง" ในเพลงดอกไม้ของชาติ) ซึ่งมุมกล้องเกิดการบดบังทางกายภาพ (Occlusion) ส่งผลให้แบบจำลอง MediaPipe ไม่สามารถตรวจจับพิกัดนิ้วมือได้อย่างสมบูรณ์ ผู้จัดทำจึงแก้ไขปัญหาโดยการพิจารณาตัดชุดข้อมูลที่ไม่สมบูรณ์ออกจากการคำนวณพาร์ทมือ และมุ่งเน้นการคัดสรรภาพนิ่งเฉพาะส่วน (Manual Cropping) ในท่ารำที่ระบบตรวจจับได้ดีเพื่อนำมาหาค่าเฉลี่ย โดยมีรายละเอียดจำนวนภาพที่ใช้ประมวลผลในแต่ละเพลงดังนี้:

1. ข้อมูลพิกัดมือและนิ้วมือ (MediaPipe Hands Dataset)
- เพลงดอกไม้ของชาติ: ใช้ภาพมือตั้งวงจำนวน 23 ภาพ (ท่าจีบส่งหลังกำหนดเป็น 0 ภาพเนื่องจากข้อจำกัดในการตรวจจับพิกัดข้างต้น)
- เพลงคืนเดือนหงาย: ใช้ภาพมือตั้งวงจำนวน 36 ภาพ และภาพมือจีบหงายจำนวน 36 ภาพ
- เพลงรำซิมารำ: ใช้ภาพนิ้วมือส่วนล่าง (ระดับเอว) จำนวน 33 ภาพ และภาพนิ้วมือส่วนบนจำนวน 33 ภาพ
2. ข้อมูลพิกัดโครงสร้างสรีระร่างกาย (MediaPipe Pose Dataset)
- เพลงดอกไม้ของชาติ:
  - ใช้ภาพวิเคราะห์โครงสร้างร่างกายรวมจำนวน 37 ภาพ
- เพลงคืนเดือนหงาย
  - ใช้ภาพวิเคราะห์โครงสร้างร่างกายรวมจำนวน 24 ภาพ
- เพลงรำซิมารำ
  - ใช้ภาพวิเคราะห์โครงสร้างร่างกายรวมจำนวน 35 ภาพ

ชุดข้อมูลพิกัดทั้งหมดในข้างต้น ได้ถูกนำมาคำนวณหาค่าเฉลี่ยคณิตศาสตร์เพื่อแปลงเป็นโครงสร้างแบบจำลองดิจิทัลอ้างอิง  สำหรับใช้เป็นเกณฑ์หลักในการเปรียบเทียบคะแนนและแสดงผล Feedback บนหน้าเว็บแอปพลิเคชัน

## 3.4 สถาปัตยกรรมของระบบตรวจจับ (System Architecture)

สถาปัตยกรรมของระบบตรวจจับและประเมินผลท่ารำไทย ถูกออกแบบขึ้นภายใต้แนวคิด สถาปัตยกรรมแบบแยกส่วน (Modular System Architecture) เพื่อแบ่งแยกหน้าที่การประมวลผลข้อมูล (Data Processing) และการคำนวณตรรกะคะแนนออกจากกันอย่างชัดเจน โดยมุ่งเน้นการประมวลผลบนฝั่งผู้ใช้งาน (Client-side Processing) ผ่านเว็บเบราว์เซอร์ เพื่อรองรับการทำงานในรูปแบบเวลาจริง (Real-time) และลดภาระการประมวลผลของเครื่องแม่ข่าย(Server)

3.4.1 ส่วนรับสัญญาณภาพเข้า

ทำหน้าที่เปิดรับกระแสข้อมูลวิดีโอ (Video Stream) จากกล้องเว็บแคมของผู้ใช้งานผ่านเทคโนโลยี HTML5 Video API โดยระบบจะทำการดักจับเฟรมภาพนิ่ง (Input Frame) อย่างต่อเนื่องตามอัตราเฟรมเรตของกล้อง (เช่น 30 เฟรมต่อวินาที) และทำการแปลงระบบสีของภาพจาก BGR เป็น RGB เพื่อเตรียมส่งต่อผลลัพธ์ให้แก่โมเดลปัญญาประดิษฐ์

3.4.2 ส่วนประมวลผลปัญญาประดิษฐ์

เฟรมภาพ RGB จะถูกส่งเข้าไปประมวลผลขนานกันภายในแบบจำลองปัญญาประดิษฐ์             จำลองพิกัด 2 ตัวหลัก ได้แก่:

1. MediaPipe Pose Model: ทำหน้าที่สกัดพิกัดโครงสร้างกระดูกและข้อต่อหลักทั่วร่างกายจำนวน 33 จุด ในรูปแบบพิกัด 3 มิติ (X, Y, Z)
2. MediaPipe Hands Model: ทำหน้าที่ดักจับโครงสร้างมือและปลายนิ้วมือทั้งสองข้างเพื่อระบุตำแหน่งพิกัดเชิงระนาบ (X, Y) สำหรับวิเคราะห์ลักษณะท่าจีบหรือตั้งวง

3.4.3 ส่วนบล็อกคำนวณตรรกะและเกณฑ์คะแนน

พิกัดเชิงพื้นที่ที่สกัดได้จากระบบ AI จะถูกส่งผ่านสถาปัตยกรรมสคริปต์ควบคุมที่แยกจากกันเป็นโมดูลเพื่อประเมินผลตามเกณฑ์ตรรกะนาฏศิลป์ (Logical Constraints):

- โมดูลวิเคราะห์สรีระร่างกาย (body.js): ทำหน้าที่คำนวณองศาเชิงเรขาคณิต เช่น มุมข้อศอก มุมเปิดไหล่ ระดับศีรษะ และโครงสร้างการย่อตัวเปรียบเทียบกับค่าโมเดลอ้างอิงอาร์เรย์ขั้นต่ำ-ขั้นสูง (Percentile 10-90)
- โมดูลวิเคราะห์โครงสร้างมือ (hand.js): ดำเนินการคัดแยกความสูงของมือเพื่อระบุ "มือหน้า/มือบน" และ "มือหลัง/มือล่าง" โดยจะมุ่งเน้นการคำนวณระยะห่างเพื่อตรวจจับการกำหมัด ท่าแบมือราบทื่อ และทิศทางปลายนิ้วเฉพาะมือหลัก เพื่อแก้ปัญหาคะแนนแกว่งจากระยะกล้อง
- โมดูลประมวลผลเด็ดขาด (allpose.js): เป็นด่านสุดท้ายที่ทำหน้าที่รับผลลัพธ์จากโมดูลสรีระและโมดูลมือ เพื่อนำมาคำนวณน้ำหนักคะแนนสุทธิตามเกณฑ์ (ตัว 50% และมือหน้า 50%) พร้อมทั้งรวบรวมอาเรย์ของข้อความผิดพลาดทั้งหมดมัดรวมเข้าด้วยกัน (Combined Feedbacks) ก่อนส่งออกไป

3.4.4    ส่วนแสดงผลลัพธ์โครงประสานผู้ใช้ (UI Rendering Layer)

ทำหน้าที่นำข้อมูลสรุปผลคะแนนสุทธิและรายการข้อความเตือนภัยที่ห่อกลับมาจากโมดูลคำนวณ นำมาอัปเดตลงบนหน้าจออินเตอร์เฟสแบบเรียลไทม์ โดยใช้ HTML DOM Injection ในการพ่นข้อความแนะนำ (Feedback) ลงกล่องข้อความ และใช้กลไกของ HTML5 Canvas ในการวาดเส้นโครงร่างมนุษย์ (Skeletal Overlay) ทับลงบนหน้าจอกล้อง เพื่อให้ผู้ใช้งานมองเห็นข้อผิดพลาดของสรีระตนเองได้ในทันที

## 3.5 กระบวนการทำงานของระบบ (System Workflow)

3.5.1 แผนผังภาพรวมการทำงานของระบบ

[ภาพ] *รูปภาพที่ 13 Flowchart การทำงานของระบบ*

แผนผังแสดงสถาปัตยกรรมการทำงานเชิงระบบ ซึ่งแบ่งออกเป็น 2 ส่วนหลัก ได้แก่ 1) กระบวนการจัดเตรียมข้อมูลอ้างอิงและสร้างแบบจำลองมาตรฐานในรูปแบบไฟล์ JSON และ 2) ลำดับขั้นตอนการทำงานบนเว็บแอปพลิเคชันแบบเรียลไทม์ ตั้งแต่การรับสัญญาณภาพจากกล้อง การสกัดจุดตัดข้อต่อร่างกาย การเปรียบเทียบค่าองศาเชิงเรขาคณิตกับเกณฑ์มาตรฐาน ตลอดจนระบบวิเคราะห์ข้อผิดพลาดเพื่อสร้างและแสดงผลคะแนนควบคู่กับข้อความแนะนำแก่ผู้ใช้งาน

3.5.2 การประมวลผลด้วยชุดกฎเกณฑ์

ระบบนำข้อมูลพิกัดข้อต่อร่างกาย 33 จุด และพิกัดโครงสร้างมือที่ได้จาก MediaPipe มาคำนวณความสัมพันธ์เชิงเรขาคณิต (Geometric Relationship) เช่น การวัดระยะห่างระหว่างปลายนิ้วเพื่อเช็กการกำหมัด และการคำนวณมุมองศาของข้อต่อในแต่ละเฟรมภาพ จากนั้นนำค่าที่ได้ไปเปรียบเทียบกับชุดกฎเกณฑ์เงื่อนไขตรรกะนาฏศิลป์ (Thresholds) ที่บันทึกไว้ในไฟล์แบบจำลองมาตรฐานเพื่อตัดสินความถูกต้องและประเมินผลคะแนน

3.5.3 การแสดงผลคะแนนและข้อความแนะนำบนระบบอินเตอร์เฟส

ระบบมีส่วนติดต่อผู้ใช้งานในรูปแบบเว็บแอปพลิเคชัน (Client-side UI) เมื่อโมดูลประมวลผล (allpose.js) คำนวณคะแนนสุทธิและคัดกรองข้อผิดพลาดเสร็จสิ้น ระบบจะทำการดึงข้อความแจ้งเตือน (Feedback Log) ออกมาจากอาเรย์อัปเดตลงบนกล่องข้อความบนหน้าจออินเตอร์เฟสทันที ควบคู่ไปกับการวาดเส้นโครงร่างมนุษย์ (Skeletal Overlay) ลงบนผืนผ้าใบ Canvas ทับบนเฟรมภาพวิดีโอสด เพื่อให้ผู้เรียนสามารถใช้ทบทวนสรีระและปรับปรุงท่วงท่ารำเบื้องต้นได้ด้วยตนเองในทันที

[ภาพ] *รูปภาพที่ 14 การแสดงผลคะแนนและข้อความแนะนำบนระบบอินเตอร์เฟส*

## 3.6 การประเมินประสิทธิภาพ

ในโครงงานนี้ผู้จัดทำได้กำหนดแนวทางการประเมินประสิทธิภาพของระบบตรวจจับและประเมินผลท่ารำไทยออกเป็น 2 ส่วน เพื่อทดสอบทั้งความถูกต้องในการตัดสินและเสถียรภาพด้านซอฟต์แวร์ ดังนี้

3.6.1 การทดสอบความถูกต้องของตรรกะการประเมินผล

ดำเนินการทดสอบโดยการนำชุดวิดีโอทดสอบ (Testing Dataset) ที่มีการจำลองพฤติกรรมการรำที่ถูกต้องตรงตามมาตรฐาน และวิดีโอที่มีการเจตนาทำท่ารำผิดเกณฑ์นาฏศิลป์ในรูปแบบต่าง ๆ (เช่น การกำหมัด, การปล่อยศอกตก, หรือการเอียงลำตัวผิดทิศทาง) มาประมวลผลผ่านระบบ จากนั้นทำการบันทึกค่าว่าระบบสามารถตรวจคัดกรองและแสดงข้อความแนะนำ (Feedback) ได้สอดคล้องตรงตามเงื่อนไขตรรกะที่ออกแบบไว้หรือไม่ โดยคำนวณออกมาเป็นอัตราส่วนร้อยละความถูกต้องของระบบ

3.6.2 การทดสอบประสิทธิภาพการทำงานแบบเรียลไทม์ (Real-time Execution Testing)

ดำเนินการวัดค่าความเร็วในการประมวลผลของเว็บแอปพลิเคชันบนเครื่องคอมพิวเตอร์ทดสอบ ผ่านการตรวจวัดอัตราเฟรมเรตเฉลี่ย (Average Frames Per Second: FPS) ในขณะทำงาน และความเร็วในการประมวลผลเชิงพื้นที่และเวลาของโมดูลคำนวณ (allpose.js) เพื่อพิสูจน์ว่าระบบสามารถตอบสนองและแสดงผล Feedback ควบคู่กับการวาดเส้นพิกัดโครงร่างบนหน้าจอได้อย่างต่อเนื่องโดยไม่เกิดปัญหาค้างหรือหน่วงช้าอันส่งผลกระทบต่อผู้ใช้งาน
